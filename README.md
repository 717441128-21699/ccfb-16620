# 铜釜与麦芽 · 精酿酒厂经营游戏

一个使用 **TypeScript + Vite + Canvas 2D + Web Worker** 实现的精酿酒厂经营模拟游戏。游戏中的四个页面、图表、按钮、滑杆和酒馆场景全部绘制在同一个 Canvas 上；20 个发酵罐的逐日发酵模拟放在 Web Worker 中计算。

## 启动

```bash
npm install
npm run dev
```

浏览器打开终端输出的地址（通常是 <http://127.0.0.1:5173>）。

生产构建与本地预览：

```bash
npm run build
npm run preview
```

类型检查：

```bash
npm run typecheck
```

公式、糖化走势、Tinseth 误差和 20 罐性能校验：

```bash
npm run verify:sim
```

## 玩法循环

1. 在 **配方实验** 中调整麦芽配比、糖化温度/时间、酒花和煮沸时间、酵母与发酵温度。
2. 到 **酿造台** 选择配方，确认库存后投料，消耗麦芽、酒花和酵母，生成待装罐麦汁。
3. 在 **发酵罐** 页把麦汁排入空罐，调整每罐发酵温度，推进游戏日。
4. 发酵完成或提前终止后装瓶/上枪；系统按实际 ABV、IBU、EBC 色度、酒体、酯类、杂醇、酚类、双乙酰和酵母健康度评分。
5. 在 **酒馆经营** 页给六个酒头选酒、调整单杯价格，接待随季节变化的顾客。
6. 用销售收入采购原料、扩建最多 20 个发酵罐。存档自动保存在 `localStorage`，采购弹窗中可重置。

季节每 9 个游戏日轮换：

- 春：淡色艾尔、花香酒花；
- 夏：皮尔森、小麦等清爽低苦酒；
- 秋：琥珀、麦芽香和 IPA；
- 冬：世涛、高酒精度和烘焙风味。

## 四个 Canvas 页面

- **酿造台**：配方卡片、双淀粉酶曲线、糖化/发酵温度调整、Tinseth 苦度明细、库存校验、投料。
- **发酵罐**：最多 20 个罐卡片、罐温滑杆、糖/比重/ABV/酵母量、发酵曲线、酯类/杂醇/酚类/双乙酰、清洗与装瓶、Web Worker 性能压测。
- **配方实验**：风格、体积、麦芽、酒花、煮沸时间、酵母的完整编辑器；实时计算 OG/FG/ABV/发酵度/IBU/EBC/酒体/成本，并内置 63°C vs 70°C 走势卡和公式自检。
- **酒馆经营**：Canvas 酒馆场景、季节窗景、顾客、六个酒头、库存/定价/上枪、14 日营收柱状图和杯量曲线。

顶部 **原料采购** 弹窗可购买 8 种麦芽、7 种酒花和 6 种酵母。所有参数均为游戏性与教材经验范围结合而虚构/调校。

## 核心模型与验收对应

### 1. 糖化：两种淀粉酶

`src/game/formulas.ts` 中：

- β-淀粉酶在约 63–65°C 活性最高，并在高温下快速失活，负责更多可发酵麦芽糖；
- α-淀粉酶在约 68–72°C 活性更高，产生较多不可发酵糊精，使酒体更厚；
- 酶的累计功同时取决于温度曲线、糖化时间和每种麦芽的 `betaPower` / `alphaPower`；
- 可发酵度还受麦芽的 `dextrinBase` 和配比影响。

默认配方的校验结果：

```text
63°C：可发酵度 77.8%，ABV 5.17%
70°C：可发酵度 58.9%，ABV 4.10%
变化：可发酵度下降 18.9 个百分点，ABV 下降 1.08
```

因此从 63°C 升到 70°C 时，可发酵度和最终酒精度均下降，酒体/糊精指数上升，走势与家酿教材中“低温干、高温厚”的经验一致。`npm run verify:sim` 会对所有初始配方检查 `F63 > F70` 和 `ABV63 > ABV70`。

### 2. Tinseth 苦度

严格使用：

```text
Utilization = 1.65 × 0.000125^(OG−1) × (1 − e^(−0.04 × boilMin)) / 4.15
IBU = αDecimal × oz × 7490 × Utilization / gal
```

代码中同时保留英制单位公式，界面上的公制克/升由单位换算得到。`U(OG=1.050, 60min) = 23.07%`。

自检用一个独立的英制逐字实现对比 5 组参数：

```text
Tinseth 最大误差：0.000%（要求 ≤ 5%）
```

### 3. 发酵与副产物

Worker 对每罐每个游戏日执行 24 个小时子步，计算：

- 温度热惯性和设定温度追踪；
- Q10 代谢速率、低温抑制、高温胁迫；
- 酵母逻辑斯蒂增长、酒精抑制；
- 剩糖消耗、比重和 ABV 轨迹；
- 酯类、杂醇、酚类和双乙酰；
- 酵母健康度、沉降/还原和发酵阶段。

高于酵母适温上限时，代谢短期加快，但酯类和杂醇按温度指数项增加，酵母健康度下降。小麦酵母和比利时酵母的酯/酚参数更高，拉格酵母更低且适温范围更冷。

### 4. 评分与销售

装瓶评分由四部分组成：

```text
总分 = 0.20×ABV匹配 + 0.20×IBU匹配 + 0.15×色度匹配 + 0.45×风味
```

风味分进一步包含酒体、酯类、酚类、杂醇、双乙酰、健康度和晚投酒花香气。风格目标定义在 `src/data/ingredients.ts`。

酒馆需求会综合：

- 装瓶总分和奖牌；
- 风格的季节亲和系数；
- 价格敏感度；
- 声望；
- 周末/日期噪声；
- 酒头是否断酒。

### 5. 20 罐 Web Worker 性能

消息协议见 `src/game/protocol.ts`，Worker 见 `src/workers/ferment.worker.ts`。酿造页和发酵页的“推进一天”都会调用 Worker；发酵罐页还有 **20罐性能压测** 按钮，会在 Worker 内模拟 20 罐 × 60 个游戏日并返回平均每日耗时。

本机校验结果（会随机器波动，但余量很大）：

```text
Node 核心循环：20 罐 × 120 日，平均 0.160ms/日，最大 1.614ms
Headless Chrome + Vite 生产包：20 罐单日 Worker computeMs ≈ 0.1–0.7ms
要求：≤ 30ms / 游戏日
```

## 目录结构

```text
src/
  data/            # 麦芽、酒花、酵母、风格和初始配方参数
  game/
    formulas.ts    # 糖化、Tinseth、色度、评分、发酵单步等纯函数
    engine.ts      # 采购、酿造、装罐、装瓶、酒馆日结等状态操作
    state.ts       # 初始存档、localStorage、种子数据
    validation.ts  # 糖化走势和 Tinseth 自检
    workerClient.ts
    protocol.ts
  workers/
    ferment.worker.ts
  ui/
    app.ts         # Canvas 框架、缩放/指针、顶栏、弹窗、主循环
    widgets.ts     # 立即模式 Canvas 面板/按钮/滑杆/滚动区域
    theme.ts
    pages/
      brewhouse.ts
      fermenters.ts
      lab.ts
      tavern.ts
      shop.ts
scripts/
  verify.ts        # npm run verify:sim 使用的 Node 校验
```

## 备注

- 游戏使用固定设计分辨率 `1366 × 860`，Canvas 会按窗口等比缩放并处理 DPR，指针坐标会反向换算到设计坐标。
- 所有数值模拟均在本地运行，不依赖外部服务。
- `scripts/gameplay-check.mjs` 与 `scripts/ui-check.mjs` 是开发期浏览器冒烟脚本，使用 `puppeteer-core` 和本机 Chrome 路径；不是运行游戏所必需的部分。
